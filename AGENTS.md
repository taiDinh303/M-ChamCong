# Coding Rules

## General

- Keep code concise and clean.
- Prefer simple solutions.
- Do not over-engineer.
- Reuse existing code before creating new code.
- Inspect the existing project before modifying it.
- Make the smallest necessary change.
- Do not create unnecessary files.
- Do not install unnecessary packages.

## Code Style

- Follow the existing project's architecture and naming conventions.
- Remove unused imports, variables and methods.
- Avoid duplicate logic.
- Keep functions focused and readable.

## HTML/CSS

- Keep short HTML elements on one line.
- Keep attributes on the same line when practical.
- Avoid unnecessary whitespace and formatting.

## Before Coding

1. Inspect the relevant files.
2. Understand the existing architecture.
3. Identify what actually needs to change.
4. Modify only the necessary files.

## After Coding

- Check for compile errors.
- Check for obvious bugs.
- Do not change unrelated code.

## Response

- Be concise.
- Explain only important changes.
- Show only relevant code.

## UI/UX Style

- Follow the visual style of https://www.marixa.one/.
- Clean, minimal, modern and professional.
- Use clear typography, generous whitespace and strong visual hierarchy.
- Use light backgrounds, dark text, restrained accent colors and subtle borders/shadows.
- Keep layouts, cards, forms and buttons simple, consistent and well aligned.
- Avoid excessive colors, gradients, animations and decoration.
- Use modern readable fonts and consistent spacing.
- For new pages, create the necessary CSS, components, assets and folders following the existing project architecture.
- Keep the design consistent across the entire application.
